# التثبيت على استضافة مشتركة (cPanel / Hostinger)

الطريقة دي لأي استضافة عادية فيها **PHP 8.4 و MySQL** — من غير SSH، من غير Redis، ومن غير Node.
كل اللي هتعمله: ترفع ملف، تعمل قاعدة بيانات، تفتح صفحة في المتصفح، وتضيف سطر Cron. حوالي ١٥ دقيقة.

> بالإنجليزي باختصار: download the release zip, upload & extract it, create a MySQL database, open `https://your-domain/install`, then add the cron line it shows you.

---

## ١. قبل ما تبدأ — جهّز الاستضافة

1. **الدومين وشهادة SSL:** اتأكد إن الدومين (أو الساب دومين، زي `academy.yoursite.com`) شغّال، وإن الشهادة مفعّلة.
   - cPanel: **SSL/TLS Status** ← لو الدومين مش أخضر اضغط **Run AutoSSL**.
   - Hostinger: **Websites ← Security ← SSL** ← فعّل الشهادة المجانية.
   - ⚠️ لوحة التحكم بتشتغل على `https` بس. من غير شهادة صفحة الدخول مش هتشتغل.
2. **إصدار PHP 8.4:**
   - cPanel: **Select PHP Version** (أو **MultiPHP Manager**) ← اختار **8.4** للدومين.
   - Hostinger: **Advanced ← PHP Configuration** ← **PHP 8.4**.
3. **إضافات PHP** (من نفس الشاشة ← **Extensions**) — اتأكد إن دول متعلّم عليهم:
   `pdo_mysql`, `mbstring`, `openssl`, `tokenizer`, `xml`, `ctype`, `json`, `bcmath`, `fileinfo`, `intl`, `zip`, `curl`, و`gd` (أو `imagick`).
   المثبّت هيفحصهم كلهم ويقولك لو حاجة ناقصة.
4. **(مستحسن)** من **Options** في نفس الشاشة: `memory_limit = 256M`، `upload_max_filesize = 64M`، `post_max_size = 64M`، `max_execution_time = 300`.

## ٢. نزّل الحزمة

من صفحة [Releases](https://github.com/Tafrah/tafra-open-lms/releases) نزّل آخر ملف باسم
`tafra-open-lms-vX.Y.Z.zip`.

الحزمة جاهزة: فيها كل المكتبات (`vendor`) والأصول المبنية (`public/build`)، ومفيهاش أي كلمات سر.
**مش محتاج Composer ولا Node.**

## ٣. اعمل قاعدة البيانات

### cPanel
1. **MySQL® Database Wizard**.
2. اسم القاعدة — مثلاً `lms` ← هيبقى `youruser_lms`.
3. اسم مستخدم وكلمة سر قوية ← هيبقى `youruser_lmsuser`. **احفظ كلمة السر.**
4. صلاحيات: علّم على **ALL PRIVILEGES** ← **Make Changes**.

### Hostinger
1. **Websites ← Databases ← Management**.
2. اكتب اسم القاعدة واسم المستخدم وكلمة السر ← **Create**.
3. الأسماء بتتكتب كاملة بالبادئة، زي `u123456789_lms`.

> السيرفر (Host) غالباً `localhost`. في Hostinger لو مااشتغلش، اكتب العنوان اللي ظاهر جنب القاعدة في نفس الصفحة.

## ٤. ارفع الملفات — اختار طريقة من الاتنين

### الطريقة الأولى (الأسهل): المشروع كله جوه `public_html`

1. **File Manager** ← افتح `public_html` (أو مجلد الساب دومين).
2. **Upload** ← ارفع ملف الـ zip.
3. كليك يمين على الملف ← **Extract** ← لو الملفات اتفكّت جوه مجلد فرعي (`tafra-open-lms-vX.Y.Z`)، انقل **كل** اللي جواه لـ `public_html` نفسه.
4. اتأكد إن ملف **`.htaccess`** موجود في `public_html` (في File Manager: **Settings ← Show Hidden Files**).

الملف ده هو اللي بيحمي المنصة: بيحوّل كل الطلبات لمجلد `public/` ومابيسمحش لأي حد يوصل لـ `.env` أو `storage` أو `vendor`.

> **لو لوحتك بتسمح تغيّر «Document Root» للدومين** (cPanel ← **Domains** ← Manage، أو للساب دومين وقت إنشائه): خلّيه يشاور على `public_html/public` — ده الأفضل والأسرع، وملف `.htaccess` اللي في الجذر مش هيتستخدم أصلاً.

### الطريقة التانية: المشروع برّا `public_html` (أأمن)

مناسبة لو عايز ملفات المشروع ماتكونش جوه المجلد العام خالص.

1. في المجلد الرئيسي لحسابك (جنب `public_html` مش جواه) اعمل مجلد اسمه **`tafra-lms`**، وارفع وفك الـ zip جواه.
2. انقل **محتوى** `tafra-lms/public/` كله (بما فيه `.htaccess` و`build/` و`installer/`) لـ `public_html`.
3. انسخ الملف `tafra-lms/deploy/shared-hosting/index.php` **فوق** `public_html/index.php`.
   الملف ده بيقول لـ Laravel إن المشروع في `../tafra-lms` وإن المجلد العام هو `public_html`. لو سمّيت المجلد اسم تاني، عدّل السطر ده فيه:
   ```php
   $app_path = dirname(__DIR__).'/tafra-lms';
   ```
4. **ماترفعش** ملف `.htaccess` اللي في جذر المشروع لـ `public_html` في الطريقة دي — الملف اللي جاي من `public/` هو الصح.

### صلاحيات المجلدات

غالباً مش محتاج تعمل حاجة. لو المثبّت قال إن مجلد مش قابل للكتابة: كليك يمين ← **Change Permissions**:
- `storage` و`bootstrap/cache` (وكل اللي جواهم): **775**
- مجلد المشروع نفسه: **755** (عشان المثبّت يكتب ملف `.env`)

## ٥. افتح المثبّت

افتح `https://your-domain.com` — هيحوّلك لوحده على **`/install`**:

1. **المتطلبات** — فحص PHP والإضافات والصلاحيات. الأخضر تمام، والأصفر تحذير مش مانع.
2. **قاعدة البيانات** — اكتب البيانات من الخطوة ٣ ← **اختبر الاتصال وكمّل**.
   لو فيه غلط هتظهر رسالة بالعربي بتقول السبب (كلمة سر غلط، المستخدم مش مربوط بالقاعدة…).
3. **المنصة والمدير** — اسم المنصة، اسمك، المادة، بريدك، موبايلك، وكلمة سر (٨ حروف على الأقل فيها حرف كبير وصغير ورقم).
4. **ثبّت المنصة** — بياخد أقل من دقيقة. ماتقفلش الصفحة.

المثبّت بيعمل لوحده: ملف الإعدادات `.env` (بمفتاح تشفير جديد، وضع الإنتاج، كل حاجة على قاعدة البيانات — مفيش Redis)، الجداول، الأدوار والصلاحيات، منصتك وحسابك كمدير (وكمالك للتثبيت كله)، ورابط الملفات.

بعد ما يخلص، `/install` بيختفي (بيرجّع 404) — مفيش حد يقدر يعيد التثبيت.

## ٦. آخر خطوة: Cron (المهام المجدولة)

صفحة النهاية بتعرض سطر زي ده — بمسار مشروعك الحقيقي:

```
* * * * * php /home/youruser/public_html/artisan schedule:run >> /dev/null 2>&1
```

- **cPanel:** **Cron Jobs** ← Common Settings: **Once Per Minute** ← الصق السطر في **Command** ← **Add New Cron Job**.
- **Hostinger:** **Advanced ← Cron Jobs** ← **Custom** ← الصق الأمر (من غير النجوم لو الشاشة بتطلب الأمر بس، واختار «كل دقيقة»).

لو الاستضافة فيها أكتر من إصدار PHP، بدّل `php` بمسار 8.4:
- cPanel (EasyApache): `/opt/cpanel/ea-php84/root/usr/bin/php`
- CloudLinux / Hostinger: `/opt/alt/php84/usr/bin/php`

**ليه مهم؟** مفيش «عامل طابور» على الاستضافة المشتركة. الكرون كل دقيقة بيشغّل عامل بيخلّص الشغل المتأجّل (الإشعارات، معالجة الصور، التصدير) ويقفل قبل الدقيقة الجاية، وكمان النسخ الاحتياطي والتنظيف. من غيره الحاجات دي مش هتحصل.

## ٧. بعد التثبيت

- **البريد:** ادخل لوحة التحكم ← الإعدادات ← البريد، وحط بيانات SMTP (من **Email Accounts** في cPanel). لحد ما تعمل كده، رسائل «نسيت كلمة السر» بتتسجّل في `storage/logs` بس.
- **النسخ الاحتياطي:** نزّل نسخة من القاعدة (cPanel ← **phpMyAdmin** ← Export) ومن مجلد `storage/app` بشكل دوري. كتير من الاستضافات فيها نسخ تلقائي (cPanel ← **Backup**، Hostinger ← **Backups**).

## الصور والملفات من غير symlink

المنصة بتحاول تعمل رابط `public/storage` (زي `php artisan storage:link`). كتير من الاستضافات المشتركة قافلة دالة `symlink()`.

وقتها **مفيش مشكلة**: المثبّت بيكتب في `.env`:
```
PUBLIC_STORAGE_URL=https://your-domain.com/uploads
```
والمنصة نفسها بتعرض الملفات العامة من `/uploads/...` (ملفات الديسك العام بس، من غير الملفات المخفية، مع كاش في المتصفح).
ده أبطأ شوية من إن السيرفر يعرضها مباشرة، بس شغّال على أي استضافة. لو الاستضافة فعّلت `symlink()` بعدين وعايز ترجع للطريقة الأسرع: اعمل الرابط من Terminal (`php artisan storage:link`) وامسح سطر `PUBLIC_STORAGE_URL` من `.env`.

## مشاكل شائعة

| المشكلة | الحل |
|---|---|
| صفحة بيضا أو **500** من أول مرة | إصدار PHP مش 8.4 للدومين ده. غيّره من Select PHP Version. |
| **403 / 404** على كل الصفحات | ملف `.htaccess` ماترفعش (مخفي). فعّل Show Hidden Files وارفعه، أو `mod_rewrite` مقفول — كلّم الدعم. |
| المثبّت بيقول `.env` مش قابل للكتابة | خلّي صلاحية مجلد المشروع **755**، أو اعمل ملف فاضي اسمه `.env` بصلاحية **644**. |
| «اسم المستخدم أو كلمة السر غلط» | الاسم لازم يكون كامل بالبادئة (`youruser_lmsuser`). |
| «المستخدم مالوش صلاحية على القاعدة» | cPanel ← MySQL Databases ← **Add User To Database** ← ALL PRIVILEGES. |
| صفحة الدخول مابتشتغلش / بترجع لنفسها | الشهادة (HTTPS) مش مفعّلة. فعّل AutoSSL. |
| الإشعارات أو الصور المصغّرة مش بتتعمل | سطر الـ Cron ناقص أو مسار PHP فيه غلط. |

## ملفات تخصّك بعد التثبيت

- `.env` — الإعدادات وكلمة سر القاعدة. **ماتشاركهوش مع حد.**
- `storage/app/installed.json` — علامة إن المنصة اتثبّتت (الإصدار والتاريخ). لو مسحته، المنصة لسه شايفة إنها متثبّتة (وضعها مقفول في القاعدة) — `/install` مش هيرجع.
